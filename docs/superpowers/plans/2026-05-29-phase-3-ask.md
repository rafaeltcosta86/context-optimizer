    "## Answers Received"

    "# Ask Report — tiny-app"
    "**Mode:** weak-state"
    "**Signal count:** 0"
    "In one or two sentences, what does this project do?"
    "What are the rules a new agent must never break"
    "What changes most frequently in the active work"
)

for assertion in "${ASSERTIONS[@]}"; do
    if [[ "$INPUT" != *"$assertion"* ]]; then
        echo "FAIL: Missing assertion: $assertion"
        exit 1
    fi
done

echo "PASS: weak-fixture ASK-REPORT validated"

- [ ] **Step 1: Replace Phase 3 stub with full procedure**

Replace the stub with:

```markdown
### Phase 3 — ASK

**Purpose:** Fill the smallest possible gap in understanding by asking the user only what cannot be inferred from files. Never re-ask what the Scan Report already answered.

**Inputs:** The Scan Report (Phase 1) and Diagnosis Report (Phase 2).

**Procedure:**

1. **Count usable signals from the Scan Report.** One signal per qualifying source:

   | Source | Counts as a signal if |
   |--------|----------------------|
   | Context file | ≥ 5 lines. "Context file" = agent config files only: `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursorrules`, `.cursor/rules/*.mdc`. `README.md` does NOT count. Multiple files each count individually. |
   | Hook | Any hook detected (project-level or global) |
   | Memory | count > 0 populated entries |
   | Project type | Clear type from manifest — not "unknown" |

2. **Branch on signal count:**

   **If count < 3 → Weak-state fallback:**

   Ask all 3 fixed questions in a single message. Wait for the user's response before continuing. Do not ask any additional questions regardless of what the Diagnosis Report shows.

   Fixed questions:
   - Q1: *In one or two sentences, what does this project do?*
   - Q2: *What are the rules a new agent must never break in this project?*
   - Q3: *What changes most frequently in the active work — issues/PRs in a tracker, tasks in a board, or something else?*

   Treat the answers as if they had been inferred from files — they feed directly into Phase 4 RECOMMEND.

   **If count ≥ 3 → Normal-state surgical questions:**

   Check the Diagnosis Report for the following triggers. For each trigger that fires, you have one question to ask. Maximum 3 questions total.

   | Trigger | Question |
   |---------|----------|
   | ≥ 2 platforms detected AND no `AGENTS.md` present | Should rules be unified in `AGENTS.md` (cross-tool) or kept per-platform? |
   | Stage signals score = 1 (exactly one weak signal, ambiguous) | Is this project organized as a sequential workflow (each folder = a stage) or is the numbering coincidental? |
   | Scan Report `## In-Flight State` shows "Skipped" or "no gh auth" | Do you want dynamic in-flight queries (requires `gh auth login`) or a static roadmap file (you maintain manually)? |

   If **0 triggers fire**: skip asking, emit ASK-REPORT immediately, proceed to Phase 4.
   If **≥ 1 trigger fires**: ask all triggered questions together in one message. Wait for the user's response. Then emit ASK-REPORT.

   **Hard rule:** never re-ask anything the Scan Report already answered. This is non-negotiable.

3. **Emit the ASK-REPORT.** Always emit this block, regardless of mode or whether questions were asked:

   ```
   ---ASK-REPORT-START---

   # Ask Report — {project name}

   **Mode:** weak-state | normal-state
   **Signal count:** N

   ## Questions Asked

   1. {question text}

   _No questions needed._ (use this when 0 questions in normal-state)

   ## Answers Received

   1. {user's answer}

   _N/A_ (use this when 0 questions)

   **Ask complete.**

   ---ASK-REPORT-END---
   ```

After the ASK-REPORT is emitted, **proceed immediately to Phase 4 — RECOMMEND** without pausing for user input.
```
